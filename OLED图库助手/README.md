# OLED 图库助手

把多张图片打包进 STM32F103C8T6 的 Flash，烧录后用 **EC11 旋转编码器**切换显示。图片以常量数组的形式编译进固件，不需要文件系统，也不占用 RAM。

- 一次导入几十张图，按列表顺序对应屏幕上的第 1、2、3… 张
- 拧编码器上一张/下一张，首尾循环
- 按下编码器，屏幕显示 `GALLERY 12/40` 这样的序号页，1 秒后自动回到图片
- 界面实时显示「已用 / 上限」张数，超容量直接拦下

> **不会自动播放**：上电显示第 1 张，只有转动 EC11 才换图。生成的 `main.c` 里没有任何定时轮播代码——如果烧进去看到图片在自己循环，那是烧了「OLED 图像助手」的工程（它的多帧就是按帧间隔循环播放的），重新点一次「一键生成并烧录」即可。

## 与「OLED 图像助手」的区别

| | OLED 图像助手 | OLED 图库助手（本软件） |
|---|---|---|
| 用途 | 单图显示 / GIF 动画播放 | 多图图库，手动切换 |
| 切换方式 | 定时自动轮播 | EC11 旋转编码器 |
| 额外硬件 | 无 | EC11 编码器（A/B/按键） |
| 生成文件 | `OLED_Image.h` + 动画 main.c | `OLED_Gallery.h` + `Encoder.c` + 图库 main.c |
| 容量提示 | 帧间隔、播放 | 张数上限、Flash 占用 |
| 认界面 | 左边是「帧序列 / 帧间隔」 | 左边是「图库图片」，顶栏写着 EC11 手动切图 |

两个软件共用同一套图像处理与 Keil 工具链代码，可以并存；双击前认准 exe 名字和窗口标题。

## 快速开始

**直接用（推荐）**

到 [Releases](https://github.com/summer-insect/-/releases) 下载 `OLED-Gallery-Assistant-v1.1-win64.zip`，解压后双击 `OLED图库助手.exe`。免安装，自带 Python 3.13 与 Qt 6 运行时，不需要装任何东西。

**从源码跑**

```bash
pip install -r requirements.txt
python main.py
# 或双击 启动.bat
```

**流程**

1. 拖入多张图片（PNG/JPG/BMP/WEBP/GIF，GIF 会自动拆帧混进图库）
2. 左栏调整取模方式 / 阈值 / 反色，看中间预览
3. 右栏「接线」页设置 OLED 与 EC11 引脚，「工程」页设置工程名与 Keil 路径
4. 点「一键生成并烧录」（或先「仅生成」）
5. 上电后拧编码器切图

## 硬件接线

| 模块 | 引脚 | 接到 |
|---|---|---|
| OLED | VCC / GND | 3.3V / GND |
| OLED | SCL / SDA | 默认 PB8 / PB9，可改 |
| EC11 | A 相 | 默认 PA0，可改 |
| EC11 | B 相 | 默认 PA1，可改 |
| EC11 | C 公共端 | **GND（固定，不接单片机）** |
| EC11 | 按键（可选） | SW 一端接默认 PA2，另一端接 GND |

**EC11 那三根线（A、B、C）到底怎么接**

EC11 本体是机械编码器，转轴下面两组触点：A、B 两相相差 90°，C 是两相的**公共端**。

```
        ┌── A ──→ PA0   （软件里选）
EC11 ───┼── B ──→ PA1   （软件里选）
        └── C ──→ GND   （固定，不占单片机引脚）
```

- 只有 A、B 需要接单片机，C 直接接电源地，**接 3.3V 会一直读低电平、完全没反应**
- A/B 使用**内部上拉**，模块自带的 4.7k 上拉不影响；整套只吃 3.3V，不要接 5V
- 有些模块标的是 `CLK / DT / SW`：CLK 当 A 相、DT 当 B 相、SW 当按键
- 三脚 EC11 没有按压开关，界面里把「按键 SW」取消勾选即可，生成代码不会占用那个引脚

右侧「接线」页的 A 相 / B 相下拉框选哪个引脚，生成的 `oled_config.h` 就按哪个引脚出宏；C 永远接 GND，所以软件里不提供选项。

## 能存多少张

图片以 `const uint8_t` 数组编译进 Flash，每张固定 1 KB（128×64÷8）。

| 项目 | 数值 |
|---|---|
| 芯片 Flash | 64 KB |
| 程序基线（库 + 驱动 + 字库 + EC11 解码） | 约 7.8 KB |
| 每张图 | 1 KB |
| 硬件理论上限 | 约 56 张 |
| 软件限制 | 55 张（留 1 张余量） |
| **MDK-Lite 未注册版实际可用** | **23 张** |

实测数据：

| 张数 | 固件大小 | MDK-Lite 编译结果 |
|---|---|---|
| 12 张 | 20088 B（19.6 KB） | ✅ 0 error 0 warning |
| 23 张 | 31396 B（30.7 KB） | ✅ 0 error 0 warning |
| 55 张 | 64292 B（62.8 KB） | ❌ L6047U 超出链接器上限 |

**关键结论：Keil 没注册的话，实际只能存 23 张左右。** 32KB 是 MDK-Lite 链接器的硬限制，不是芯片的限制。界面在超过 23 张时显示黄色警告，超过 55 张时红色阻止；真的超限导致编译失败时，日志会给出中文提示而不是原始 `L6047U`。

超过 55 张时软件会禁用生成并提示删减；如果改参数导致程序变大而装不下，Keil 链接阶段会报 Flash 溢出错误。

## 转了没反应怎么查

先点界面右下角的「EC11 自检」，它会烧一个只显示电平和计数的固件（不含图片），屏幕四行：

```
EC11 SELF TEST
A1 B1 ISR:1234
EDGE:   12
STEP:    3
```

| 现象 | 说明 | 处理 |
|---|---|---|
| A/B 随旋转翻转、EDGE 跟着增减 | 接线正常，是解码阈值问题 | 把「每格脉冲」改成 2，重新生成 |
| A/B 一直不变（比如恒为 1 1） | A/B 没接到选定的引脚，或模块没供电 | 用万用表量模块 VCC-GND 是否有 3.3V；确认 A/B 真的插在 PA0/PA1 上 |
| A/B 不变、且 C 接 GND 后毫无反应 | 少数模块是下拉型，公共端要接 3.3V | 把 C 从 GND 改接 3.3V 再试（两种接法都不会烧板子） |
| A/B 会变，EDGE 一直是 0 | 定时中断没跑（软件问题） | 把这现象反馈给我 |
| EDGE 会变，STEP 一直是 0 | 解码凑不满一格 | 「每格脉冲」改成 2 |

**验证引脚本身好不好用**：自检固件运行时，用一根杜邦线把 PA0 碰一下 GND，屏幕上的 `A` 应该立刻从 1 变 0，松手回 1。变说明单片机引脚正常，问题在编码器或线上。

自检完再点一次「一键生成并烧录」，图库固件就写回去了。

## EC11 手感不对怎么调

这是最常见的调试点，在右栏「接线」页改，改完重新生成烧录：

| 现象 | 原因 | 处理 |
|---|---|---|
| 转一格跳两张 | 每格产生的边沿数少于阈值 | 「每格脉冲」改成 **2** |
| 转了没反应 | 每格边沿数多于阈值 | 改成 **8** |
| 方向相反 | A/B 接反 | 勾「反向」 |
| 按键没反应 | 引脚错或未接地 | 检查 SW 引脚；不用按键就取消勾选 |
| 偶尔跳一格 | 编码器磨损或线太长 | 缩短接线，或把「每格脉冲」调到 8 |

默认值 4 对应「一格 = 一个完整正交周期」，绝大多数 EC11 模块都是这个规格。

## 生成的文件

```
输出/OLED_Gallery/
├─ Hardware/
│  ├─ oled_config.h      引脚与参数（OLED + EC11），改接线只改这里
│  ├─ OLED.c             江协 OLED 驱动，引脚走宏
│  ├─ Encoder.c/.h       EC11 驱动（TIM3 1ms 扫描 + 状态机）
│  └─ OLED_Data.c/h      字库与图形
├─ User/
│  ├─ OLED_Gallery.h     图库点阵（GAL_Frame00… + GAL_ImageTable）
│  ├─ main.c             图库主循环：切图 + 序号页
│  └─ stm32f10x_it.c
├─ Library/ Start/ System/   标准外设库
└─ OLED_Gallery.uvprojx  Keil 工程（已自动加入 Encoder.c、开 hex 输出）
```

生成的 C 代码里，切图逻辑就三行核心：

```c
step = Encoder_GetStep();          // +1 / -1 / 0
if (step) Gallery_Step(step);      // 越界自动首尾循环
// Gallery_Step 内部：算索引 → OLED_ShowImage → OLED_Update
```

## 实现说明

**为什么把图片编译进 Flash，而不是运行时写入？**

运行时写内部 Flash 需要擦页（1KB/页）、处理写保护、还要额外的传输通道（串口/USB）来送图。而图库的使用场景是「选好图 → 烧一次 → 长期使用」，编译进固件最简单可靠：读取零开销、不怕掉电、不需要文件系统。代价是换图要重新烧录。

**EC11 解码为什么不用外部中断？**

机械编码器抖动会产生大量边沿，外部中断容易被抖动打爆。这里用 TIM3 每 1ms 采样一次 A/B 电平，查 16 项状态表得到跳变方向，累加到阈值才输出一步——抖动在累加过程中被自然抵消，而且中断负载恒定。

**按键为什么要 20ms 消抖？**

同一中断里对 SW 连续采样，只有低电平持续满 20 次（20ms）才认为按下，松手时才产生一次事件，避免长按重复触发。

## 已知限制

- 只支持 SSD1306 128×64 单色；1.3 寸 SH1106 需把列偏移改成 2
- 图片统一用同一套取模参数，适合风格相近的一组图；差异极大的图建议分批做
- 图片数量上限受 Flash 约束，不能像 SD 卡那样扩展
- 软件 I2C 全屏刷新约 10~20ms，切图有轻微延迟，属正常
- 每次生成会覆盖同名工程目录，手改过的代码会丢，建议换工程名

## 开发

打包：

```bash
python -m PyInstaller --noconfirm --clean --windowed --name "OLED图库助手" --icon assets/app.ico --add-data "assets;assets" main.py
```

调试参数：`python main.py --demo`、`--screenshot out.png`。

模块职责与「OLED 图像助手」一致，差异集中在两处：

- `app/codegen.py`：生成 `OLED_Gallery.h`、图库版 `main.c`、含 EC11 段的 `oled_config.h`，并把 `Encoder.c/.h` 写进 uvprojx
- `app/main_window.py`：右栏拆成「接线 / 工程」两个标签页，新增 EC11 配置卡片与容量条
