# OLED 图库助手 · 交接文档

> 一个 Windows 桌面小工具：把多张图片批量转成 SSD1306 的 128×64 单色点阵，以常量数组编译进 STM32F103C8T6 的 Flash，自动生成可编译的 Keil 工程并一键烧录；上电后用 EC11 旋转编码器切换图片。
>
> 交接对象：接手维护 / 二次开发的同学。读完后应能独立跑起来、定位「转不动 / 跳格 / 装不下」这三类问题、并安全地改动生成逻辑。
>
> 与「OLED 图像助手」共用图像处理与工具链代码，**两边的差异集中在 `codegen.py` 与 `main_window.py`**，本文只讲差异与图库特有部分。

---

## 1. 快速上手（5 分钟）

### 1.1 直接运行（推荐给使用者）

到仓库 [Releases](https://github.com/summer-insect/-/releases) 下载 `OLED-Gallery-Assistant-v1.1-win64.zip`，解压后双击 `OLED图库助手.exe`。免安装，自带 Python 3.13 与 Qt 6 运行时。

> 源码目录里的 `dist\OLED图库助手\OLED图库助手.exe` 是同一份程序；`dist/` 不进 Git。

首次启动会在 exe 同级生成 `config.json`（记住上次参数）与 `输出\`（生成的 Keil 工程）。

### 1.2 从源码运行（推荐给维护者）

```bash
pip install -r requirements.txt      # PySide6-Essentials>=6.6、Pillow>=10.0
python main.py                       # 或双击 启动.bat
```

### 1.3 首次使用流程

1. 拖入多张图片（PNG/JPG/BMP/WEBP/GIF；GIF 自动拆帧，混进图库）
2. 左栏调「取模方式 / 阈值 / 反色」，中间实时预览当前选中的那张
3. 右栏「接线」页设 OLED 与 EC11 引脚，「工程」页设工程名与 Keil 路径
4. 点「一键生成并烧录」；上电后拧 EC11 切图，按下编码器显示 `GALLERY 3/12`

> 三个调试参数：`--demo`（造几张示例图）、`--screenshot out.png`（无头截图，用于验证界面）。

## 2. 硬件前提

| 项目 | 要求 |
|---|---|
| 单片机 | STM32F103C8T6（64KB Flash / 20KB RAM） |
| 屏幕 | SSD1306，128×64，I2C（VCC/GND/SCL/SDA），默认 SCL→PB8、SDA→PB9 |
| 编码器 | EC11（A/B 两相 + 公共端 C；带按键的型号为 5 脚） |
| 编码器接线 | A→默认 PA0、B→默认 PA1、**C→GND（固定）**、SW→默认 PA2 且另一端接 GND |
| 烧录器 | ST-Link（SWD：SWDIO/SWCLK/GND/3V3） |
| 工具链 | Keil MDK 5（UV4.exe）+ Keil.STM32F1xx_DFP ≥ 2.2.0 |

**最容易踩的接线坑**：把 C 接到 B 的排针位上。此时 B 被钉在 GND，只有 A 相在跳，正交状态机看到的是「半个周期」，永远凑不满 `ENC_STEPS_PER_DETENT`，现象就是「怎么转都不换图」。遇到这类反馈，先让用户烧「EC11 自检」固件，看屏幕上的 A/B 是否随旋转翻转。

EC11 是机械触点，A/B 用**内部上拉**（`GPIO_Mode_IPU`），公共端必须接 GND；接 3.3V 会一直读低电平。整套系统只用 3.3V，PA0/PA1 不是 5V 容忍脚。

## 4. 数据流

```
用户拖入 N 张图
   ↓ imaging.load_frames()        统一缩放成 128×64 灰度，GIF 拆帧
   ↓ imaging.process_all()        按选项二值化（阈值/抖动/误差扩散/自适应）
   ↓ 每帧 1024 字节（8 页 × 128 列）
   ↓ codegen.build_gallery_header()   →  GAL_Frame00 … GAL_Frame{N-1} + GAL_ImageTable[N]
   ↓ codegen.build_main_c(N)          →  图库主循环（切图 + 序号页）
   ↓ codegen.build_oled_config()      →  oled_config.h（OLED 引脚 + EC11 引脚/参数）
   ↓ 拷贝模板其余文件、_patch_uvprojx() 加入 Encoder.c、开 hex 输出
   ↓ toolchain.build() / flash()      →  UV4.exe -b / -f，解析日志给出中文结论
输出/工程名/  ← 可直接用 Keil 打开、编译、下载
```

运行时（固件侧）：

```
TIM3 每 1ms 中断 → A/B 采样 → 16 项状态表累加 s_acc
主循环 → Encoder_GetStep() 返回 +1/-1/0 → Gallery_Step(step) → 换索引 → OLED_ShowImage → OLED_Update
```

## 5. 关键设计（改动前必读）

### 5.1 为什么把图片编译进 Flash，而不是运行时写 Flash

图库场景是「选好图 → 烧一次 → 长期使用」。编译进固件：读取零开销、不怕掉电、不需要文件系统，也不用额外传输通道（串口/USB）送图。代价是换图要重新烧录。

如果将来要做「运行时换图」，需要：按页擦除（1KB/页）、处理写保护、加一个上传协议（串口或 USB DFU），并且图片区和代码区要做地址规划——这是一次架构级改动，不要顺手改。

### 5.2 图库点阵的存储格式

`User/OLED_Gallery.h` 里每张图是一个独立的常量数组，再配一张指针表：

```c
const uint8_t GAL_Frame00[1024] = { ... };
const uint8_t GAL_Frame01[1024] = { ... };
...
const uint8_t *const GAL_ImageTable[GAL_COUNT] = { GAL_Frame00, GAL_Frame01, ... };
```

用指针表而不是二维数组，是为了让链接器按 1KB 对齐放置、也方便以后做「按需加载」。`GAL_COUNT` 由界面上的图片数量决定，生成时写死。

### 5.3 EC11 解码：为什么不用外部中断

机械编码器抖动会产生大量边沿，外部中断容易被抖动打爆，而且不同模块的抖动时间差异很大。这里用 **TIM3 每 1ms 采样**一次 A/B：

- `TIM3` 时钟 72MHz / 72 = 1MHz，`TIM_Period = ENC_SCAN_MS * 1000 - 1`，即 1ms 溢出
- 中断里把 `(A<<1)|B` 组成 2 位状态，用 16 项表 `ENC_TABLE[(prev<<2)|cur]` 得到本次跳变方向，累加到 `s_acc`
- `Encoder_GetStep()` 里累加值达到 `±ENC_STEPS_PER_DETENT` 才输出一步并清零 → 抖动被累加过程自然抵消
- 临界区用 `__disable_irq()/__enable_irq()` 保护 `s_acc`

`ENC_STEPS_PER_DETENT` 默认 4（一格 = 一个完整正交周期），对应绝大多数 EC11。半周期模块要改成 2；磨损严重或线太长导致误跳时改成 8。

### 5.4 按键消抖

同一个 1ms 中断里对 SW 计数：低电平持续满 20 次（20ms）才算按下，松手瞬间置一次事件。这样长按不会重复触发，`Encoder_ButtonEvent()` 取走即清零。

### 5.5 自检固件（转不动时的第一诊断工具）

`codegen.build_selftest_main_c()` 生成一个**不需要图片**的固件，屏幕四行：

```
EC11 SELF TEST
A1 B1 ISR:1234
EDGE:   12
STEP:    3
```

- `A1 B1`：A/B 实时电平，转动时应翻转
- `ISR`：定时中断计数，用来确认 1ms 中断在跑
- `EDGE`：状态表累计的跳变数（带符号）
- `STEP`：当前累计值与阈值的关系，达到阈值时清零并 +1

对应关系：`A/B` 不动 → 接线/供电；`EDGE` 不动但 `A/B` 动 → 中断没跑；`EDGE` 动但 `STEP` 不动 → 阈值太大。

界面上「EC11 自检」按钮走的是 `generate(..., selftest=True)`：不写 `OLED_Gallery.h`，只换 `main.c`，生成到独立工程名 `EC11_Test`，不影响原图库工程。

### 5.6 容量与 MDK-Lite 上限

```python
FLASH_TOTAL   = 64 * 1024
PROGRAM_RESERVE = 8 * 1024        # 库 + 驱动 + 字库 + 解码的粗略基线
MAX_IMAGES      = (64*1024 - 8*1024)//1024 - 1        # 55
LITE_MAX_IMAGES = (32*1024 - 8*1024)//1024 - 1        # 23（未注册 MDK-Lite 的链接器上限）
```

实测（AC5，DFP 2.4.0）：

| 张数 | Program Size | 结果 |
|---|---|---|
| 3 张（用户实机工程） | Code 4080 / RO 6776 | 0 error 0 warning |
| 12 张 | 20088 B（19.6 KB） | 0 error 0 warning |
| 23 张 | 31396 B（30.7 KB） | 0 error 0 warning |
| 55 张 | 64292 B（62.8 KB） | ❌ `L6047U` 超链接器上限 |

界面在 >23 张时黄色警告、>55 张时红色阻止；链接阶段仍溢出时 `toolchain.build_error_hint()` 会把 `L6047U` 翻成中文提示，而不是甩原始错误码。

## 7. 已知限制

- 仅支持 SSD1306 128×64 单色；1.3 寸 SH1106 需把列偏移改成 2
- 图片共用一套取模参数，风格差异大的图建议分批做
- 换图必须重新烧录（见 5.1）
- 软件 I2C 全屏刷新 10~20ms，快速连续旋转时会有轻微滞后，属正常
- 每次生成覆盖同名工程目录，手改代码会丢，建议换工程名
- 未注册 MDK-Lite 只能装约 23 张

## 8. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 图片自动循环播放 | 烧的是图像助手工程 | 重新点「一键生成并烧录」 |
| 转编码器不换图 | ① C 接错位置 ② 模块没供电 ③ A/B 没插在选定引脚 ④ 阈值过大 | 先烧「EC11 自检」看 A/B 和 EDGE；再看「每格脉冲」 |
| 转一格跳两张 | 每格边沿少于阈值 | 「每格脉冲」改 2 |
| 方向相反 | A/B 接反 | 勾「反向」 |
| 按键没反应 | SW 未接或未接地；三脚编码器无按键 | 检查 SW 引脚；不用就取消勾选 |
| 编译报 `L6047U` | 超过 MDK-Lite 32KB | 删图到 23 张以内，或注册 Keil |
| 屏幕全黑 | SCL/SDA 接反、I2C 地址不对、没共地 | 对照接线页，确认 0x78/0x7A |
| 生成失败提示引脚冲突 | PA13/PA14 被选（SWD 占用） | 换引脚；PA15/PB3/PB4 会自动关 JTAG 保留 SWD |

## 9. 二次开发指引

**加一种取模算法**：`app/imaging.py` 加 `METHOD_*` 常量与处理函数 → `process_frame()` 里分支 → `main_window.py` 的下拉框加一项。预览与点阵共用同一份数据，不需要改预览。

**加一个新硬件外设（比如蜂鸣器提示）**：
1. `codegen.EncoderConfig` 旁边加一个 `BuzzerConfig`
2. `build_oled_config()` 生成对应宏
3. `assets/template/Hardware/` 放驱动，`_patch_uvprojx()` 里加入工程
4. `build_main_c()` 里调用

**改主循环行为**（比如长按进入自动播放）：改 `build_main_c()` 生成的 C 字符串。注意这里是**字符串模板**，改完一定要生成一个工程、用 Keil 编译验证，别只看 Python 语法。

**改界面**：`main_window.py` 用 `_xxx_card()` 工厂方法拼卡片，右栏是 `QTabWidget`（接线 / 工程）。整窗最小 1060×660，右栏卡片高度敏感，加内容前先确认 880px 高度还装得下。

**重新打包**：

```bash
python -m PyInstaller --noconfirm --clean --windowed --name "OLED图库助手" \
  --icon assets/app.ico --add-data "assets;assets" main.py
```

⚠️ PyInstaller 的 COLLECT 阶段会**删掉 `dist/OLED图库助手` 整个目录**——如果用户在里面生成过工程，先备份 `输出\` 与 `config.json`，或者用 `--distpath dist_new` 打到别处再合并。

## 10. Git 与发布

- 仓库根是 `图片显示软件/`，同时容纳两个软件；图库助手与图像助手各自独立打包、独立发布

- **发布流程**：打包 → 压缩 `dist/OLED图库助手` 为 `OLED-Gallery-Assistant-vX.Y-win64.zip` → `gh release create` 挂附件 → 源码改动单独提交
- 版本记录：`v1.0` 仅含图像助手；`v1.1` 起包含图库助手，两套 zip 一起发
