# OLED 图像助手 · 交接文档

> 一个 Windows 桌面小工具：把任意图片/GIF 转成 SSD1306 的 128×64 单色点阵，自动生成可编译的 Keil 工程，并可通过 ST-Link 一键烧录到 STM32F103C8T6。
>
> 交接对象：接手维护/二次开发的同学。读完后应当能独立跑起来、定位问题、改动功能。

---

## 1. 快速上手（5 分钟）

### 1.1 直接运行（推荐给使用者）

到仓库的 [Releases](https://github.com/summer-insect/-/releases) 页面下载 `OLED-Image-Assistant-v1.1-win64.zip`，解压后双击 `OLED图像助手.exe`。免安装、自带 Python 与 Qt 运行时。

> 如果本机已有源码目录，`dist\OLED图像助手\OLED图像助手.exe` 是同一份程序（dist 不进 Git，只存在于打包过的那台机器）。

首次启动会在 exe 同级目录生成 `config.json`（记住上次参数）和 `输出\`（生成的 Keil 工程）。

### 1.2 从源码运行（推荐给维护者）

```bash
pip install -r requirements.txt
python main.py
# 或双击 启动.bat（内部用 pythonw 启动，不弹黑框）
```

依赖只有两个：`PySide6-Essentials>=6.6`、`Pillow>=10.0`。

### 1.3 首次使用流程

1. 拖入图片（PNG/JPG/BMP/WEBP/GIF，GIF 自动拆帧；多张图 = 动画）
2. 左栏调「取模方式 / 阈值 / 反色」，中间 128×64 实时预览
3. 右栏确认 SCL/SDA 引脚、I2C 地址、工程名与输出目录
4. 点「一键生成并烧录」（F5），或「仅生成工程」（Ctrl+G）

## 2. 硬件前提

| 项目 | 要求 |
|---|---|
| 单片机 | STM32F103C8T6（64KB Flash / 20KB RAM） |
| 屏幕 | SSD1306，128×64，I2C 接口（4 针：VCC/GND/SCL/SDA） |
| 默认接线 | SCL→PB8，SDA→PB9（可在界面任意改） |
| 烧录器 | ST-Link（SWD：SWDIO/SWCLK/GND/3V3） |
| 工具链 | Keil MDK 5（UV4.exe）+ Keil.STM32F1xx_DFP 器件包 |

驱动是**软件 I2C**（GPIO 模拟开漏输出），不占用硬件 I2C 外设，所以引脚可以随便挑。

## 4. 数据流

```
图片文件
  │ imaging.load_frames()         PIL 打开，GIF 逐帧拆成 Frame(image, name, size)
  ▼
Frame（原始 RGBA）
  │ imaging.process_frame()       铺底→旋转镜像→自动裁白边→等比/裁剪/拉伸→亮度对比度→取模→打包
  ▼
Frame.data: bytes（1024 字节 = 128×64/8，SSD1306 页格式：8 页 × 128 列，低位在上）
  │ codegen.build_image_header()  转成 C 数组，每帧一个 const uint8_t[1024]
  ▼
User/OLED_Image.h
  │ codegen.generate()            拷模板 + 写配置/驱动/点阵/main + 改工程文件名与 DFP 版本
  ▼
<工程名>/<工程名>.uvprojx
  │ toolchain.build()             UV4.exe -b（命令行编译，轮询 build.log）
  │ toolchain.flash()             UV4.exe -f（走工程里预置的 ST-Link 配置下载）
  ▼
STM32 运行，屏幕亮
```

界面上的预览用的是同一份 `Frame.data` 反向解包（`imaging.unpack`），所以**预览所见 = 屏幕所示**，不存在两套渲染逻辑。

## 5. 关键设计（改动前必读）

### 5.1 为什么用「模板工程 + 参数替换」而不是拼字符串

从零生成一套 Keil 工程需要启动文件、标准外设库、分散加载、uvprojx 的几十个字段，手写极易出错且无法保证编译通过。这里的做法是：

- `assets/template/` 放一份**已经能编译通过**的完整工程；
- 生成时整目录拷贝，只覆盖 4 个文件：`Hardware/oled_config.h`、`Hardware/OLED.c`、`User/OLED_Image.h`、`User/main.c`；
- 再改写 `Project.uvprojx` 的 `<OutputName>`、`<CreateHexFile>`、`<PackID>`。

好处：编译链路永远跟模板一致；坏处：换芯片型号/换驱动要同步改模板。**不要**在生成时去改 `Library/` 或 `Start/`。

### 5.2 引脚参数化

`Hardware/OLED.c.tpl` 是模板里的驱动源码，把硬编码的 `GPIOB / GPIO_Pin_8 / RCC_APB2Periph_GPIOB / 0x78 / X += 2` 换成了宏：

```c
GPIO_WriteBit(OLED_SCL_PORT, OLED_SCL_PIN, (BitAction)BitValue);
RCC_APB2PeriphClockCmd(OLED_SCL_CLK | OLED_SDA_CLK, ENABLE);
{{JTAG_REMAP}}                 // 用到 PA15/PB3/PB4 时插入关闭 JTAG 的代码
OLED_I2C_SendByte(OLED_I2C_ADDR);
X += OLED_COL_OFFSET;          // SSD1306 填 0，SH1106 填 2
```

`codegen.build_oled_config()` 生成这些宏，`build_oled_c()` 只负责替换 `{{JTAG_REMAP}}` 占位符。注意模板里**不保留** `OLED.c` 原文件，只有 `.tpl`，避免两处不同步。

引脚合法性在 `codegen.PIN_NOTES` 里声明，分三级：

- `error`：PA13/PA14（SWDIO/SWCLK）—— 选了就禁用「生成并烧录」按钮，因为占了就再也烧不进去；
- `warn`：PA15/PB3/PB4（自动关 JTAG，保留 SWD）、PA9/PA10（USART1）；
- `info`：PC13~PC15 驱动能力弱、PB2 影响 BOOT 等，只提示不拦截。

### 5.3 DFP 版本自适应

`uvprojx` 里的 `<PackID>` 写死了器件包版本，版本不匹配 Keil 会报 missing pack。`toolchain.pack_versions()` 扫 `<Keil根>/ARM/PACK/Keil/STM32F1xx_DFP/` 下的版本目录，取最大版本号填进去。换电脑部署时不需要改代码。

### 5.4 编译与烧录

```
UV4.exe -b <project>.uvprojx -j0 -o build.log     # 编译
UV4.exe -f <project>.uvprojx -j0 -o flash.log     # 下载
```

要点：

- 用 `subprocess.Popen` 起进程，每 150ms 增量读日志文件（`_stream_log`），实现界面上实时滚动；日志是 **GBK** 编码，用 `errors="replace"` 兜底。
- UV4 的退出码不可靠：编译返回 1 可能只是 warning。所以 `-b` 以日志里的 `0 Error(s)` 为准，`-f` 以退出码 0 为准。
- 超时 300 秒强制 kill，避免 Keil 弹窗卡死界面。
- 烧录失败时 `flash_message()` 会把典型英文错误翻译成人话（没检测到 ST-Link / 连不上芯片 / Flash 写入被拒）。
- 调试器配置（ST-Link、SWD、Flash 算法）来自模板的 `Project.uvoptx`。**如果接手人用 J-Link 或 DAP-Link，需要在 Keil 里改一次 Options for Target → Debug，或改模板 uvoptx。**

### 5.5 线程模型

所有耗时操作（生成工程、编译、烧录）都在 `widgets.TaskThread`（QThread 子类）里跑，通过 `line / done / failed` 三个信号回主线程。主线程只用 `self._busy` 一个标志控制按钮可用性。**不要在 UI 线程里直接调 `toolchain.build()`**，会卡死。

### 5.6 图像处理要点

- `_flatten()`：透明图先铺底。背景透明的图标默认铺白底；但如果透明区域超过 15% 且可见像素平均亮度 > 170（说明主体是浅色），改铺黑底 —— 否则白底白图会整片糊掉。
- `_fit_into_canvas()`：`fit`（等比留黑边）/ `fill`（等比裁切）/ `stretch`（拉伸）三选一，再叠加 `scale` 百分比和像素级偏移。缩放走 `_progressive_resize()`：**先逐级减半（BOX 面积平均），再缩到目标尺寸**，替代原来一步 LANCZOS——大比例缩小时 LANCZOS 的插值核会跨几十像素取样，产生振铃并把细节抹成均匀灰。
- `sharpen`（界面上的「清晰度」）：缩放后按 `UnsharpMask(radius=1.0, percent=sharpen*2.2, threshold=3)` 做反锐化，把已被平均成浅灰的细线拉回阈值以内。默认 60；`0` 完全关闭，`nearest`（像素画模式）下强制不锐化。
- 四种取模：`threshold`（固定阈值，适合线稿/纯色）、`bayer`（4×4 有序抖动，适合照片，纹理稳定）、`floyd`（误差扩散，层次最好但噪点散）、`mean`（局部均值自适应，适合背景光照不均）。
- `otsu_threshold()`：在**处理后的灰度图**上算 Otsu，所以「自动取阈值」会跟随缩放/亮度变化，不是固定常数。
- `pack()`：`img.tobytes()` 对模式 `"1"` 的位序正好符合 SSD1306 页格式（每字节低位在上），前提是图像尺寸严格 128×64 且模式为 `"1"`。

## 6. 功能清单

**导入**：PNG/JPG/BMP/WEBP/GIF、拖拽、多选、GIF 自动拆帧、帧列表上移/下移/删除（Delete 键）。

**处理**：四种取模 + Otsu 自动阈值、反色、自动裁白边、像素画模式（最近邻）、等比/裁剪/拉伸、缩放 20~150%、水平/垂直偏移、旋转 0/90/180/270、水平/垂直镜像、亮度、对比度、恢复默认。

**预览**：128×64 实时预览（整数倍放大、可开网格）、原始图/点阵双栏、帧切换、导出预览 PNG、点阵字节数与点亮像素统计。

**工程**：任意 SCL/SDA（PA0~PA15、PB0~PB15、PC13~PC15）、I2C 地址 0x3C/0x3D、列偏移、工程名、输出目录、单帧静态 / 多帧动画（间隔可调）、自动生成开关、生成后自动打开 Keil。

**烧录**：自动检测 Keil、一键编译+烧录、日志实时输出、失败原因翻译、状态标签、打开工程目录。

**其他**：参数持久化到 `config.json`、紧凑/宽屏自适应布局、异常写 `错误日志.txt`。

## 7. 验证状态（重要）

已实测通过：

- 生成工程 → `UV4 -b` 编译 **0 error 0 warning**（Code ≈ 2.1KB，单帧）
- 单帧走静态 `main()`（无 while 轮询闪烁），多帧走带 `Delay_ms` 的循环
- GIF 拆帧、透明 PNG、3000×2000 大图（处理耗时 < 100ms）
- JTAG 引脚（PA15/PB3）自动插入 `GPIO_Remap_SWJ_JTAGDisable`
- 无烧录器时 `UV4 -f` 的失败被正确捕获并给出人话提示

**未实测**：

- 实物点屏效果（手上无板）—— 驱动沿用原工程验证过的江协代码，风险主要在接线和列偏移

接手后第一件事建议：拿板子跑一次「一键生成并烧录」，确认这两项。

## 8. 已知限制

| 限制 | 说明 / 规避 |
|---|---|
| MDK-Lite 32KB 代码限制 | 每帧占 1KB，满屏库约 16KB，建议 ≤ 12 帧；界面会提示 |
| 只有单色 | 只支持 1bpp；灰度需换驱动 + 改 `pack()` |
| 固定 128×64 | 尺寸常量在 `imaging.OLED_W/H`，改尺寸要同步改驱动与 `OLED_Update` 的分页逻辑 |
| 软件 I2C | 全屏刷新约 10~20ms，够 20fps 以内动画；要高帧率需改硬件 I2C 或 SPI |
| 依赖 Keil | 没有 Keil 就不能编译烧录；可另接 arm-none-eabi + pyocd，但需重写 `toolchain.py` |
| 只认 ST-Link | 模板 uvoptx 里配的是 ST-Link；换调试器要在 Keil 里改 |
| 无工程历史 | 每次生成会**整目录覆盖**同名工程（`shutil.rmtree`），改过的手写代码会丢。要保留请换工程名 |

## 9. 常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 生成后编译报 missing pack | 没装 STM32F1xx_DFP，或版本探测失败；Keil 里装包，或在界面手动指定 UV4 后重新生成 |
| 编译报 `cannot open source input file "stm32f10x.h"` | 模板 `Library/` 缺失；重新拷贝 `assets/template` |
| 烧录提示「未检测到 ST-Link」 | USB 没插好 / 驱动没装（装 ST-Link Utility 或 STM32CubeProgrammer 自带驱动） |
| 烧录提示「连不上芯片」 | 检查 SWDIO/SWCLK/GND/3V3；板子是否供电；BOOT0 是否被拉高 |
| 屏幕全黑 | 先确认 SCL/SDA 有没有接反；I2C 地址试 0x3D；1.3 寸屏把列偏移改成 2 |
| 屏幕花屏/错位 | 列偏移不对（SH1106 要 2）；或分辨率不是 128×64 |
| 图案反了（黑底变白底） | 勾「反色」；白底黑线的图默认会自动反色，可能判断错了 |
| 图案糊成一团 | 换「有序抖动」或调低阈值；照片类图不要用固定阈值 |
| 动画很卡 | 降低帧数或加大间隔；软件 I2C 全屏刷新的物理上限 |
| 改了引脚不生效 | 生成的是新工程，需重新「一键生成并烧录」，不是改完就生效 |

### 11.1 什么进仓库，什么不进

| 内容 | 是否入库 | 说明 |
|---|---|---|
| 源码、Keil 模板、文档 | ✅ | 约 3MB |
| `取模工具/`（含 71.8MB 演示视频） | ✅ | 参考素材，首次 clone 会慢一些 |
| `OLED图像助手/dist/` | ❌ | 打包产物，改用 Release 分发 |
| `build/`、`__pycache__/`、`输出/`、`config.json` | ❌ | 见 `.gitignore` |

exe 不进 Git 的原因：Git 对二进制不做差异存储，改一行代码重新打包就会完整存一份 131MB 的副本，历史迅速膨胀且无法回收。Release 附件不占仓库体积，也不影响 clone 速度。

### 11.2 发新版本（重新打包后）

```bash
cd OLED图像助手

# 1. 打包，产物在 dist/
python -m PyInstaller --noconfirm --clean --windowed --name "OLED图像助手" --icon assets/app.ico --add-data "assets;assets" main.py

# 2. 压成 zip（放仓库外，避免被 Git 追踪）
#    注意：要压 dist 的上一级，让 zip 里保留 OLED图像助手/ 这一层目录；
#    并且排除 config.json 与 输出/，那是本机运行时数据，不该进 Release
python -c "import shutil; shutil.make_archive('OLED-Image-Assistant-v1.1-win64','zip','dist')"

# 3. 发 Release（tag 自动建在默认分支最新提交上）
gh release create v1.1 "OLED-Image-Assistant-v1.1-win64.zip" --repo "summer-insect/-" --title "v1.1" --notes "更新说明"

# 4. 源码改动照常提交
git add -A && git commit -m "..." && git push
```

> `gh release create` 在仓库外执行时必须带 `--repo summer-insect/-`，否则会报 `fatal: not a git repository`。

注意顺序：先提交源码再发 Release，否则 tag 会指向旧提交。若已发错，删掉重发：

```bash
gh release delete v1.1 --yes
git push origin :refs/tags/v1.1
```

### 11.3 历史说明
