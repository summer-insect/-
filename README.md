# OLED 桌面工具集 · STM32F103C8T6 + SSD1306

两个 Windows 桌面软件，共用同一套图像处理与 Keil 工具链：把任意图片转成 128×64 单色点阵，自动生成可直接编译的 Keil 工程，并通过 ST-Link 一键烧录。

| | [OLED 图像助手](OLED图像助手/) | [OLED 图库助手](OLED图库助手/) |
|---|---|---|
| 用途 | 单图显示 / GIF 动画播放 | 多图图库，手动切换 |
| 换图方式 | 定时自动轮播（帧间隔可调） | **EC11 旋转编码器**，转动切图 |
| 额外硬件 | 无 | EC11 编码器（A / B / 按键） |
| 图片存放 | 帧数组，播放时逐帧送屏 | 每张 1KB 常量数组，编译进 Flash |
| 生成文件 | `OLED_Image.h` + 动画 `main.c` | `OLED_Gallery.h` + `Encoder.c` + 图库 `main.c` |
| 认界面 | 左栏是「帧序列 / 帧间隔」 | 左栏是「图库图片」，顶栏带 `EC11 手动切图` |
| 容量上限 | 建议 ≤ 12 帧（MDK-Lite） | 55 张（MDK-Lite 下实际 23 张） |

两个软件可以并存，互不干扰：图像助手面向「一张图 / 一段动画」，图库助手面向「一柜子图，拧一下就翻」。

---

## 一、OLED 图像助手

- 导入即预览，128×64 所见即所得（预览和点阵用同一份数据）
- 四种取模算法（固定阈值 / 有序抖动 / 误差扩散 / 自适应）+ Otsu 自动阈值
- SCL、SDA 引脚任意选，JTAG 引脚自动避让，SWD 引脚直接拦截
- GIF 自动拆帧，按设定帧间隔循环播放
- 生成完整 Keil 工程（标准外设库 + 江协 OLED 驱动），命令行编译、烧录、日志实时回显

## 二、OLED 图库助手

- 一次导入几十张图，按列表顺序对应第 1、2、3… 张
- 拧 EC11 上一张 / 下一张，首尾循环；按下编码器显示 `GALLERY 12/40` 序号页
- 图片以 `const uint8_t` 编译进 Flash，读取零开销，不需要文件系统与外部存储
- 界面实时显示「已用 / 上限」张数，超容量直接拦下
- 内置 **EC11 自检固件**：转不动时先烧它，屏幕直接显示 A/B 电平、中断计数、边沿数、步数，一眼区分「线接错了」和「阈值不对」

> **不要搞混**：图库固件里没有任何定时轮播代码，上电停在第 1 张，只有转编码器才换图。如果烧进去看到图片自己在循环，那是烧了图像助手的工程。

## 快速开始

**直接用（推荐）**

到 [Releases](https://github.com/summer-insect/-/releases) 下载对应压缩包，解压到任意目录，双击 exe：

| 软件 | Release 附件 | 解压后 |
|---|---|---|
| OLED 图像助手 | `OLED-Image-Assistant-v1.1-win64.zip` | `OLED图像助手.exe` |
| OLED 图库助手 | `OLED-Gallery-Assistant-v1.1-win64.zip` | `OLED图库助手.exe` |

免安装，自带 Python 3.13 与 Qt 6 运行时，不需要装任何东西。

**从源码跑**

```bash
pip install -r OLED图像助手/requirements.txt

python OLED图像助手/main.py      # 图像助手
python OLED图库助手/main.py      # 图库助手
```

**典型流程**

1. 拖入图片（PNG / JPG / BMP / WEBP / GIF）
2. 左栏调取模方式、阈值、反色，中间实时预览
3. 右栏设引脚（图库版还有 EC11 的 A/B/SW）与工程名，选 Keil 路径
4. 点「一键生成并烧录」，或先「仅生成」拿到工程
5. 图像助手按帧间隔自动播放；图库助手拧 EC11 切图

## 硬件接线

| 模块 | 引脚 | 接到 |
|---|---|---|
| OLED | VCC / GND | 3.3V / GND |
| OLED | SCL / SDA | 默认 PB8 / PB9，软件里可改 |
| EC11（仅图库助手） | A 相 | 默认 PA0，软件里可改 |
| EC11（仅图库助手） | B 相 | 默认 PA1，软件里可改 |
| EC11（仅图库助手） | C 公共端 | **GND（固定，不占单片机引脚）** |
| EC11（仅图库助手） | 按键 SW | 默认 PA2，另一端接 GND；三脚编码器可关闭 |

EC11 只有 A、B 接单片机，C 是两相的公共端，必须接 GND——**把 C 接到 B 的位置是新手最常犯的错**：B 被钉在低电平，只剩 A 相在跳，正交解码永远凑不满一格，表现就是「怎么转都不换图」。五脚模块标 `CLK / DT / SW` 的，CLK 当 A、DT 当 B、SW 当按键。

## 使用环境

### 一、运行环境（把软件跑起来）

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11（64 位） | 依赖 Qt 6，并用注册表定位 Keil；未在 32 位系统与 Win7 上测试 |
| 运行方式 A | 直接运行 exe，**无需装 Python** | Release 包自带 Python 3.13 与 Qt 运行时 |
| 运行方式 B | Python 3.10 及以上 | 依赖 `PySide6-Essentials ≥ 6.6`、`Pillow ≥ 10` |
| 屏幕分辨率 | 建议 1366×768 及以上 | 窗口最小尺寸 1060×660，再小会显示不全 |
| 磁盘空间 | 图像助手约 110MB / 图库助手约 160MB | 解压后目录体积，另加每个生成的 Keil 工程约 2MB |

### 二、编译烧录环境（点「一键生成并烧录」时需要）

| 项目 | 要求 | 说明 |
|---|---|---|
| Keil MDK | 5.x，需含 `UV4.exe` | 自动从注册表及 `C:\Keil_v5`、`D:\keil5`、`E:\…` 等常见路径查找，找不到可在界面手动指定 |
| 编译器 | ARMCC V5.06（AC5） | 模板工程按 AC5 配置；改 AC6 需在 Keil 里改 Target 设置 |
| 器件包 | Keil.STM32F1xx_DFP ≥ 2.2.0 | 生成时读取本机已装版本写进工程（实测 2.4.0），换电脑不用改代码 |
| 调试器 | ST-Link（SWD 模式） | 模板预置 ST-Link；J-Link / DAP-Link 需在 Keil 里改一次 Debug 选项 |
| 驱动 | ST-Link USB 驱动 | 装 STM32CubeProgrammer 或 ST-Link Utility 时一并装好 |

> 只点「仅生成工程」时，Keil、ST-Link 都不是必需的——工程可以拷到别的机器上编译。

### 三、硬件环境（决定显示效果）

| 项目 | 要求 |
|---|---|
| 单片机 | STM32F103C8T6（64KB Flash / 20KB RAM） |
| 显示屏 | SSD1306，128×64，I2C 四针（VCC / GND / SCL / SDA） |
| 屏幕兼容 | 1.3 寸 SH1106 也可用，但需把「列偏移」改成 2，否则画面左移两列 |
| 默认接线 | SCL→PB8，SDA→PB9；可改成任意 GPIO（PA13/PA14 除外，那是 SWD） |
| 烧录接口 | SWD：SWDIO(PA13)、SWCLK(PA14)、GND、3V3 |
| 供电 | 3.3V；OLED 模块若标称 5V 供电，模块一般自带稳压，可直接接 5V；EC11 只接 3.3V |

### 四、不需要准备什么

- 不需要联网（首次安装 Python 依赖除外）
- 不需要装 Python（使用 exe 时）
- 不需要单独装驱动（装过 Keil + ST-Link 的机器通常已具备）
- 图库助手不需要 SD 卡、文件系统或上位机通信

## 已知限制

- 仅支持单色 128×64 SSD1306；驱动为软件 I2C，全屏刷新约 10~20ms，动画帧率上限约 20fps
- **MDK-Lite（未注册）有 32KB 代码限制**：图像助手建议 ≤ 12 帧，图库助手实际 ≈ 23 张（芯片 64KB 理论可到 55 张）
- 每次生成会覆盖同名工程目录，手改过的代码会丢，建议换工程名
- 图库图片共用一套取模参数，适合风格相近的一组图；换图需重新烧录
- 图库容量受 Flash 约束，不能像 SD 卡那样扩展
